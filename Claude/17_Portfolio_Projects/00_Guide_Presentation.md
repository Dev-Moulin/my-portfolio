# Guide de Présentation des Projets — Portfolio Paul Moulin

## Principes Clés

### Format : Étude de Cas (pas une fiche technique)
Chaque projet doit raconter une **histoire** : Problème → Réflexion → Solution → Impact.
Un recruteur veut voir **comment tu penses**, pas juste ce que tu as codé.

### Ton à adopter
- **Voix active** : "J'ai conçu...", "J'ai implémenté..." (pas "Un système a été développé")
- **Professionnel mais personnel** : ta personnalité doit transparaître
- **Technique mais accessible** : un recruteur non-tech doit comprendre l'impact global
- **Concis et scannable** : paragraphes courts, bullet points, sous-titres clairs
- **Storytelling léger** : raconter le parcours sans en faire un roman

---

## Structure par Projet

```
1. HERO VISUEL
   → Screenshot principal, GIF animé ou vidéo courte du projet en action

2. TITRE + TAGLINE
   → 1 phrase qui résume le projet et son impact
   → Ex: "Pulse — Plateforme de vote décentralisée pour les communautés Web3"

3. CONTEXTE / PROBLÈME
   → Quel besoin ? Quel contexte ? (perso, hackathon, formation)
   → Pourquoi ce projet existe-t-il ?

4. SOLUTION / APPROCHE
   → Description de l'approche technique et pourquoi ces choix
   → Architecture haut niveau

5. STACK TECHNIQUE
   → Technologies listées avec badges visuels
   → Justifier les choix techniques clés

6. FONCTIONNALITÉS CLÉS
   → 3-5 features principales avec captures/GIFs
   → Focus sur ce qui est unique ou impressionnant

7. DÉFIS & DÉCISIONS TECHNIQUES
   → Problèmes rencontrés et solutions trouvées
   → C'est LA section qui montre ta capacité de réflexion

8. RÉSULTATS / IMPACT
   → Métriques si possible (perf, users, temps)
   → Apprentissages clés

9. LIENS
   → Demo live | Code source | README

10. RÉFLEXION (optionnel mais apprécié)
    → Ce que tu ferais différemment aujourd'hui
    → Ce que ce projet t'a apporté
```

## Ce Qui Impressionne les Recruteurs

| Critère | Pourquoi ça compte |
|---|---|
| **Vrais problèmes résolus** | 60%+ des recruteurs priorisent ça — un projet utile > un clone de tutorial |
| **Résultats quantifiés** | "Réduit le temps de chargement de 40%" marque les esprits |
| **Diversité des projets** | 70% des hiring managers veulent voir front, back, full-stack |
| **Code propre & documenté** | 80% des top employeurs attendent du code lisible |
| **Le processus, pas juste le résultat** | Montre tes itérations, tes choix d'archi, tes compromis |
| **3-5 projets solides** | Qualité > quantité, toujours |

## Erreurs à Éviter

1. **Pas de contexte** — juste des screenshots sans expliquer le problème
2. **Descriptions génériques** — "Site web avec React" = trop vague
3. **Liens cassés / démos hors-ligne** — tester régulièrement
4. **Ignorer le mobile** — portfolio non responsive = signal très négatif
5. **Sauter la phase "processus"** — ne montrer que le résultat final
6. **Ne pas quantifier l'impact** — s'arrêter à "j'ai livré le projet"

## Projets Perso vs Pro

### Projets personnels / hackathons
- **Ne pas les cacher** : ils montrent passion, initiative, autonomie
- **Être transparent** sur le contexte : "Projet hackathon", "Projet d'apprentissage"
- **Mettre l'accent sur** : ce que tu as appris, tes décisions en autonomie, ta réflexion
- Un projet perso ambitieux qui résout un vrai problème = autant de poids qu'un projet pro basique

### Projets professionnels
- Mentionner le contexte business (si autorisé)
- Séparer "produit final" (équipe) et "ta contribution"
- Détailler les contraintes réelles (délais, scale, legacy)

---

## Visuels — Non Optionnels

- **GIFs animés** : idéaux pour montrer un flux utilisateur, une interaction
- **Screenshots haute qualité** : vues clés, idéalement dans un mockup device
- **Vidéos courtes** (2-5 min max) : pour les projets complexes
- **Diagrammes d'architecture** : pour les projets back-end ou full-stack
- **Demo live déployée** : rien ne remplace l'expérience directe

## Formule d'Écriture

**Mauvais :**
> "Site e-commerce avec React, Node.js et MongoDB."

**Bon :**
> "Application e-commerce full-stack conçue pour réduire l'abandon de panier.
> J'ai implémenté un système de lazy loading qui a réduit le temps de chargement de 40%,
> ainsi qu'un checkout simplifié en 3 étapes."

### Technique :
1. Commencer par le **problème**, pas par la techno
2. Utiliser des **verbes d'action** : conçu, implémenté, optimisé, réduit, augmenté
3. **Quantifier** dès que possible
4. Montrer la **chaîne causale** : "J'ai fait X → ce qui a permis Y → résultant en Z"

## Application à Ton Profil

Tu as un profil **très intéressant** pour un portfolio :
- **Web3 + 3D + Full-stack** = rare et différenciant
- **Hackathons** (Base Batch Europe, ETH Global) = crédibilité communauté
- **Diversité technique** : Ruby, TypeScript, Three.js, Solidity/Wagmi, XState
- **Projets variés** : extension Chrome, NFT platform, voting dApp, 3D visualization, community platform

### Stratégie recommandée :
- Présenter les projets du **plus impressionnant au moins impressionnant**
- Mettre en avant la **spécialisation Web3 + 3D** comme différenciateur
- Pour chaque projet, identifier le **"wow factor"** technique unique
- Lier les projets entre eux pour raconter une **progression de carrière**
